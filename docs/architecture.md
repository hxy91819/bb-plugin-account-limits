# Source architecture

```text
Host-local optional CLI Proxy -> normalized provider snapshot -> SQLite cache --+
BB Account Pooler public RPC -> normalized provider snapshot -> owner cache ----+-> source registry -> dashboard
                                                                              +-> source-specific refresh
```

The domain types are `QuotaAccount`, `ProviderSnapshot`, `QuotaSourceId` and `AccountLimitsPanelSnapshot` in `contract.ts`. The older `cliproxy*` wire names are retained only for upgrade compatibility. Sources own availability, discovery, authentication, errors and caching; the shared UI owns cards, folds, account/pool aggregation, recovery segments and weekly pacing.

- `sources.ts`: small `QuotaSource` interface and registry. Selects one source for targeted refresh, skips explicitly unavailable adapters and isolates failures.
- `config.ts`: host-local optional configuration. The default proxy is `null`; no executable paths or account identities are embedded.
- `host.ts`, `usage.ts`: CLI Proxy adapter. `cliproxyStatus` reads configuration only. Unconfigured hosts do no quota I/O. Tokens are substituted by CLI Proxy for authoritative usage endpoints; verified cached signals are a fallback. Antigravity discovers its project/plan and reads `retrieveUserQuotaSummary` on `daily-cloudcode-pa` with the versioned `antigravity/hub/2.9.1` compatibility identity. A bare user agent can omit Gemini on daily, while production can return untouched Gemini placeholders for active daily accounts. Valid complete daily data, including real zero usage, stays authoritative. An incomplete or unusable daily summary may query production once: missing families are appended without replacing measured daily families; a failed fallback retains usable daily data. Authentication/rate-limit failures and cancellation are not retried. Model catalog discovery is independent of quota summary selection.
- `server.ts`: host discovery, proxy cache and public RPC/CLI wiring. `createPanelSnapshotReader` checks host configuration before considering cached quota; removing configuration clears old proxy rows. Empty config does not become an error source. Hosts with no previous data and no reachable adapter stay absent.
- `native-provider-panel.ts`: discovers usage-capable providers on each connected BB machine and calls the public `system.usageLimits` maintenance API per provider. No separate login or proxy configuration is needed. Authentication and failures stay provider-local; targeted refresh preserves other providers. The verified built-in Codex and Claude maintenance handlers fetch upstream usage on every request, so successful collections record their local completion time and can support weekly pacing. Other providers have no freshness guarantee in this API and retain null timestamps, including forced reads. Discovery failures retain the previous observation with a cache warning. Accounts on different machines remain separate.
- `account-pool-panel.ts`: consumes only Account Pooler's public `provider-usage.v1.listResources/getResource`. An unavailable installed source retains its last observation with a warning. Account Pooler is listed only once because it is shared across machines.
- `usage-source.ts`: exposes only proxy resources to BB's native Provider Usage consumer; it does not export Account Pooler back into itself. Discovery is cache-only. Existing resource IDs are retained.
- `pool-reset.ts`: selects the earliest reported weekly reset batch, retaining unused accounts and each individual remainder/state. It reuses per-account weekly pace quality checks, keeps overdue observations pending, and marks unreported reset times explicitly.
- `pool.ts`, `pool-recovery.ts`, `weekly-pace.ts`: pure shared calculations. Sources and independent window identities are never combined. Missing all-model weekly quota is isolated, not interpreted as unlimited.
- `quota-presentation.ts`, `quota-ui.ts`: shared frontend snapshot/request deduplication, browser-scoped failure/reminder preferences, presentation-only filtering and threshold-crossing tracking. Each tracker quietly seeds its first usable snapshot, including when browser history is absent or unreadable; empty, failed and overdue-only startup observations do not consume this baseline. Windows discovered later are also seeded quietly on first observation. Only subsequent observed crossings produce toasts. Reminder history uses the versioned localStorage key `account-limits.alert-history.v1`, stable source/machine/provider/account/window identities, and the last observed threshold/reset cycle. The tracker validates persisted data and falls back to per-page memory when storage is unavailable; no credentials or quota snapshots are stored in this history. When a connected, error-free Account Pooler has usable Codex windows, the shared presentation layer prefers it over native Codex entries for both panels and reminders; a failed or empty pool restores native entries. Other providers such as Cursor SDK remain visible. Raw observations and provider routing are unchanged. Compact service cards reuse `groupAccountPools` and `aggregateCliproxyPool`, summarize weekly budgets before session/model windows, keep independent families explicit, and derive pacing colors from each pool. Generous pace uses the theme success color in cards, badges, values and bars; each model family carries its own pace and hover label. Short-term blocking and critical usage keep warning precedence. A mixed Claude card shows only the measured all-model weekly pool, marks incomplete account coverage with `*`, and explains excluded accounts in its hover detail; it does not infer missing quota or combine model caps. If no total week is reported, the card remains unknown. Any partially covered summary window carries the same marker. Expanded details retain the separate missing-total-week pool. They stay pooled when expanded details switch to accounts. Legacy flattened windows are first grouped by their account labels. The app-wide monitor refreshes visible windows every five minutes and cleans up timers/listeners on unmount.
- `app.tsx`, `panel-styles.ts`: source-level native disclosure controls, scoped host-token CSS, source/provider refresh, theme-aware custom SVG glyph. Fold state is local to this browser and independent of account/pool and display mode.

## Required pool compatibility rule

Pool accounts only within the same account type and subscription tier. Different types or tiers must remain separate even when they share a source, provider or quota-window name: Google AI Ultra and Google AI Pro are separate pools. Capacity weights do not make different tiers compatible.

Apply this boundary before computing percentages, reset/recovery forecasts and weekly pacing. The full dashboard, compact service cards and exposed pool summaries must use the same grouping, while retaining the existing source, model-family and missing-total-week boundaries.

`groupAccountTypes` in `pool.ts` normalizes the source-reported `planLabel` (case, whitespace and cached suffix), then `groupAccountPools` applies the existing Claude weekly-availability split inside each type. Account identity labels, absent plans and failed queries remain in an unidentified cohort, separate from every known tier; the dashboard does not infer their subscriptions. Existing unidentified-only data retains its legacy grouping. No cross-tier capacity ratio is guessed.

Full-panel pool sections and compact service cards use these same type boundaries. Compact cards select and show details for one type; model-family windows remain separate within each card. Coverage and partial-data stars count only that type. Public quota resources use stable type-qualified pool IDs; existing account resource IDs are unchanged. Legacy untyped pool IDs remain valid only for the unidentified cohort, and removed or changed pools fail lookup instead of silently selecting a different tier.

To add a source, extend the source ID schema, implement a `QuotaSource` adapter returning normalized accounts with stable window IDs and real observation times, register it in the server and add its presentation name. Include tests for absence, source failure, targeted refresh, incomplete measurements and model-window identity. Do not embed another service's authentication or storage rules into shared pool logic.

No live tokens, prompts, machine addresses, named personal accounts or agent launch wrappers are packaged. The host must be able to reach its configured service; a UI client does not need that access. Credentials remain host-local. Source Git installs are built by BB; release archives also include the generated portable bundles and their SDK metadata.

Execution adapters must be installed independently of this dashboard. ACP launch commands, environment values, skills and supported controls belong to BB's `acp-extensions.customAgents` settings. Optional compatibility adapters run as separate executables; this dashboard never registers them. Disabling or upgrading this dashboard must not unregister those providers.
